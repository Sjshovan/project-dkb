Add a digest-pinned Linux CLI management image and an internal typed owner
transport for Library initialization, inspection, Collection operations and
interrupted-mutation recovery without a running Runtime. Reject remote Docker
contexts, unsupported volume drivers/options, raw commands and mismatched
images; bound execution/output and clean up cancelled operation containers.
Add typed Docker Library handles to host inventory, owner-aware context
resolution, verified volume registration, checked/unchecked listings, and public
offline inspection/Library/Collection/recovery routing. Refresh associated local
Runtimes by Library identity after mutation. Share strict CLI event validation
with Console; cooperative Node IPC cancellation waits for owner cleanup on
Windows. Unsupported host filesystem operations fail closed. Authenticated
network lifecycle, Runtime/Stack volume integration, backups and migration remain
required before this becomes a supported complete Docker deployment path.

Queue offline Library and Collection writes before read-side context validation.
Locate an interrupted Library by its durable ledger only for ownership admission;
then validate its actual state under the existing writer lease. Live writers no
longer cause competing writes to report false recovery failures, while abandoned
journals and concurrent reads still fail closed.

Refresh vulnerable locked runtime dependencies and the development MCP client
within their existing major versions. Require patched Fastify and MCP client
versions; provider integrity receipts must be regenerated by the normal build.

Report safe Evidence-worker transport failure categories after confirmed cleanup,
without echoing service responses, source content or worker credentials. Retain
fail-closed termination checks and never retry compilation implicitly.

Confirm owned worker state after failed Docker stop/kill acknowledgements before
escalating or cleaning up. A stopped worker no longer requires a redundant kill;
replacement containers or uncertain termination still preserve recovery state.

Retain bounded, allowlisted Runtime transport failure categories through nested
fetch causes without exposing arbitrary exception text or credentials. Failed
management calls remain single-attempt and include endpoint recovery guidance.

Bind the Console's actual server before choosing its final URL and security
origin. Default-port collisions fall back to an OS-assigned loopback port;
explicit occupied ports fail without leaking startup resources. Isolate HTTP
tests on OS-assigned ports instead of racing over the user's Console port.

Journal the Library Registry configuration and manifest together, reject reads
during pending recovery, and preserve both files across errors and process death.
Allow only the exact configuration file through a dedicated mutation API; generic
control-state writes remain forbidden. Route Registry-default changes through
the same native or Docker-owner CLI, update host association after commit, and
refresh serving Runtimes only when the setting changes. Retain endpoint checks
and credentials on the host; no network is enabled inside the owner worker.

Report unconfirmed Docker creation separately when an acknowledgement is missing
and no operation container is yet visible. A delayed daemon request may still
create that container; do not claim cleanup is complete from one empty listing.

Treat only native process Runtime paths as locally accessible state. Query,
read, read-targets and Pipeline inspection for Docker/remote Runtimes use the
authenticated endpoint even when inventory retains an old host path. Failed
requests never fall back to that path; local Pipeline preparation rejects it
before opening state or compiling anything.
