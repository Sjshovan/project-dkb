Hard-cut plugins to the validated API v3 SDK, add trusted multi-recipe Registry
builds, centralize Runtime activation and audited retrieval, and expose the
resulting trust and build chains through the CLI and Console. API-v3 plugins
can declare canonical external service, image, and model digests while keeping
operational settings outside Evidence and Retrieval profile identity.

Retain validated semantic provider execution receipts in v2 Evidence and
Retrieval locks, bind each Retrieval Build to its exact parent Evidence
receipt, and reject malformed receipt data before build promotion. Keep
operational diagnostics in compilation reports so cache hits and timings do
not invalidate reproducible build identity.

Validate derived Evidence catalogs against canonical IR and reject warm query
contexts after selected configuration, plugin/dependency code, or exact build
inputs change. Serialize activation recovery with promotion, deduplicate cold
context opens, and revalidate Library state before releasing audited responses.

Generate bundled provider distribution receipts from shipped files and the
exact dependency closure. Verify the packaged baseline before provider import
and after distribution installation; never regenerate it on a read or install
path. Keep filesystem-only operator plugins supported without a new manifest.

Keep the distribution catalog inert. Resolve higher-priority overrides before
verified lazy imports, bind module reuse to the admitted identity, and retain
separate setup/options/state for concurrent provider hosts.

Reject bundled literal imports of unrecorded helpers, escaping files, and
undeclared dependencies before executing the module. Verification-only
package inspection does not import provider code.

Bundle exact runtime dependencies inside deployable provider archives using
native npm staging. Reverify the original receipt after staging and installation;
keep the generic SDK independently consumable. Inspect and retain one complete
candidate set, and block publication before any upload when a required package
remains private. Never silently repack or omit a required workspace.
Run inspection through the trusted host SDK rather than allowing candidate
dependency code to supply its own verifier.

Propagate packaging cancellation through native npm commands and wait for child
closure before removing staging directories. Keep exact offline dependency and
tamper checks intact. Reuse host image attestation in service proof composition
and distinguish embedding-component benchmarks from whole-system acceptance.

Honor Registry polling intervals and Retry-After timestamps even when a timer
wakes early, without extending the operation's original deadline.

Bind embedding-cache reuse to complete provider integrity and semantic options;
reject credential-bearing schema defaults before setup; generate plugin peers
against the installed distribution's SDK version. Separate definition inspection
from executable provider conformance. Reuse trusted retained and published
Registry variants before requesting compilation, preserving reader-only access.

Inspect literal module dependencies with syntax-aware parsing rather than text
matching. Preserve Node-compatible TypeScript stripping and exact shipped-file
checks without executing plugin code during inspection. Tighten public
conformance to the production embedding, index-count, readiness, scope, and
health contracts, and clean up only validated newly created managed indexes
when a conformance operation fails.

Require explicit parser source and chunk-span provenance, preserve it through
processors, and provide a checked MiniSearch lexical Pipeline using the public
SDK without an embedding dependency. Validate the recipe being saved even when
`pipeline set --no-activate` retains the previous default suggestion.

Record rejected-before-admission queries without fabricated build identities,
use unique cross-process audit event IDs, and finalize the persisted response
before delivering read-only observers. Roll back only exact newly created
managed indexes; preserve other retained spaces and report cleanup failures.

Expose versioned compiler capabilities with complete provider integrity and
boot-bound compiler identity. Carry cancellation through staged compiler work
and refuse late publication after cancellation. Keep Registry writes bound to
the requested trusted recipe and compiler identity.

Preserve trusted Stack recipes and explicit image pins across restarts, keep
publication defaults separate from allowlists, and replace configuration
atomically without an absent-file fallback window. Report unresolved optional
recipes without fabricated identities or private plugin errors; reject their
compilation and alias matching while retaining healthy recipes and exact signed
downloads. Keep Stack stop and logs available when recipe configuration is broken.

Keep original source hashes and asset anchors stable across rich, plain, and
fallback parsing. Require original source hashes from the Evidence worker,
reject obsolete or mismatched derived record caches, and hash each rich source
only once. Package-owned SQLite records retain their database path and row
locator; reject paths escaping the compilation root. Remove manifest-controlled
live database ingestion: source authors supply immutable snapshots, while
trusted operator plugins own any custom connection behavior.

Serialize destination-file promotions with bounded Windows sharing retries,
never unlinking an authoritative file before replacement. Journal Stack
configuration and topology changes separately from Runtime activation. Preserve
the prior serving configuration on failure, recognize a committed activation
after a lost response, and retain actionable recovery state when concurrent
changes or failed restoration prevent safe rollback.
